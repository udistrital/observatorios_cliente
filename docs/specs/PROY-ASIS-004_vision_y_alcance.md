# PROY-ASIS-004 — Visión y alcance SDD del frontend

## Historia de Usuario (AS-IS)
**Como** equipo funcional/técnico
**Quiero** un alcance documental claro del frontend
**Para** priorizar cambios verificables en navegación e integración API.

## Criterios de aceptación funcionales
1. Debe quedar explícita la visión del repositorio.
2. Debe delimitarse el alcance AS-IS y evolución TO-BE.

---

## Problema funcional
Sin una visión unificada, el backlog y las specs pueden divergir del objetivo del sistema.

## Objetivo del usuario
Consolidar alcance documental vigente del cliente.

## Impacto institucional
- Mejora gobernanza de cambios frontend.
- Alinea prioridades entre UI y contratos backend.

### Evidencia verificable

- `docs/flujos.md`
